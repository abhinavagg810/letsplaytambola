# Test plan — Letsplaytambola, player-facing side

Pass 1 of 2. This plan covers everything a host or a player touches. The admin panel and the analytics capture are
being rebuilt and get their own pass afterwards.

The results of running this plan are in [`QA_REPORT_USER.md`](QA_REPORT_USER.md) (plain language) and
[`results-user.json`](results-user.json) (one entry per case id).

## 1. Scope

**In scope**

| Area | What |
|---|---|
| Website | `/` (every section), header and mobile menu, code box, Notify me, FAQ, `/privacy`, `/terms`, the 404 page, page titles and link previews, `robots.txt`, `sitemap.xml` |
| Host setup | `/host` and `/host/prizes`: names, game name and chips, ticket price, "Deal me a ticket", presets, 26 patterns, prize amounts, the draft, creating the game |
| Joining | by link, by code (`/join`), wrong/finished/full games, duplicate names, coming back on the same device, a new identity after clearing storage, joining a live game |
| Game `/g/CODE` | lobby, live game (calling, auto-call, voice, dabbing, claims, win banner, prize money, board, players), results, play again |
| Public API | `POST /api/games`, `GET /api/games/:code`, `POST /api/games/:code/act`, `POST /api/notify` |
| Rules | the engine in `src/core` (tickets, 26 patterns, prize money) and the browser data layer in `src/lib` |
| Qualities | security, privacy of tickets, concurrency, resilience to bad networks, responsive layout, accessibility, performance |

**Out of scope for this pass:** `/admin/**`, `/api/admin/*`, `/api/t` and the analytics capture, the Supabase SQL schema.
(One thing was noted for that pass — see the report, "Notes for the admin/analytics pass".)

**Expected behaviour comes from** `docs/design_handoff/README.md` plus the owner's later decisions: desktop live layout
(caller + controls + ticket + Ways to win left, board + players right); players as a list with Host/Player, prizes and
total; prize amounts typed per way to win, or the ticket money split at start; the lobby share card without link text or
"Share another way"; ads off unless configured and only in the lobby and on results; games unusable after 24 h idle; a
pattern can be picked once; one player may win several prizes; 100 players at most.

## 4. Approach

- **Every case is executed**, not reviewed. Automated cases assert on what the screen shows and on what the server
  holds, and each records what was actually observed (numbers, timings, text) in `results-user.json`.
- **A test that cannot fail is not a test.** The suite was first run against the build as received: the cases for the
  known defects failed there (double-speed auto-call, small ticket cells, missing headers, the Notify-me rules, the
  missing link-preview picture…). While fixing the ticket size, the edge-tap case caught a mistake in the fix itself
  (cells overlapping) before it shipped.
- **An independent second opinion for the rules.** The end-to-end suite re-implements the 26 patterns and the voice text
  from the design's seed data, without importing the app's code, and compares the server against it (API-21, LIVE-04).
- **Three layers:** Vitest for rules and data (fast, exact) → API cases over HTTP with many device tokens (roles,
  privacy, races, limits) → browser cases with several devices in one game (what people see).
- **Regression:** every fix has a test. The durable suite lives in the repo: `npm test` (393 tests) and `npm run e2e`
  (113 cases, about 3 minutes). One-off measurements (Lighthouse, axe, load, ads-on build) were run from scratch scripts.
- **Random numbers:** the server draws the numbers, so cases play until the needed thing happens and deal a new game in
  the rare event that the round ends first.

Priorities: **P0** the game cannot be played fairly without it · **P1** important, has a workaround · **P2** minor ·
**P3** cosmetic.

## 5. Entry and exit

- Entry: the production build starts; `npm test` passes.
- Exit: every P0/P1 case passes or has an owner decision recorded; `npx tsc --noEmit`, `npm run lint`, `npm test`,
  `npm run build`, `npm run smoke` and `npm run e2e` pass.
